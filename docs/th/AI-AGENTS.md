# เอเจนต์ AI: พื้นผิวควบคุม

COPG-VD ยินดีต้อนรับผู้ร่วมพัฒนาที่เป็น AI และเอเจนต์ และทั้งโมดูลถูกสร้างขึ้นเพื่อให้ขับเคลื่อนแบบ
headless ได้ โดยไม่ต้อง scrape WebUI มีพื้นผิวอยู่สองแบบ และเอเจนต์ที่ทำงานในฐานะ root (เช่นเดียวกับที่
WebUI ทำ) ใช้ทั้งสองแบบ:

1. **ไฟล์การตั้งค่า** `/data/adb/COPG-VD/COPG-VD.json` - แหล่งความจริงหนึ่งเดียว ทุกฟิลด์ของโปรไฟล์และ
   ทุกการตั้งค่าอยู่ที่นี่, การอ่านและเขียนไฟล์นี้คือวิธีที่คุณเปลี่ยนสิ่งที่โมดูลสปูฟ
2. **จุดเข้าเชลล์** `fingerprint-update.sh` - สคริปต์หนึ่งตัวพร้อม verb ที่เสถียรสำหรับการตรวจสอบ
   การนำไปใช้ และการดึงโปรไฟล์

## ไฟล์การตั้งค่า

`/data/adb/COPG-VD/COPG-VD.json` เป็นออบเจกต์ JSON ธรรมดา โมดูลอ่านไฟล์นี้จากโปรเซสที่ถูกแทรกผ่านกฎ
SELinux เฉพาะที่มันจัดส่งมาเอง, มันไม่เก็บข้อมูลรับรองใด ๆ ตัวอย่างที่มาพร้อมอยู่ที่
`module/COPG-VD.json.example` ซึ่งรีเฟรชทุกวันจาก Google factory image ที่ใหม่ที่สุด

กฎที่เอเจนต์ต้องปฏิบัติตาม:

- **สตริงใช้เครื่องหมายอัญประกาศคู่เท่านั้น** เช่นเดียวกับใน JSON
- **ทุกฟิลด์เป็นตัวเลือก** ฟิลด์ที่ไม่ได้ระบุจะถูกข้ามและคงค่าของ ROM เองไว้
- คีย์ระดับบนสุดที่ควบคุมโมดูลคือ `scope_mode`, `scope_whitelist`, `scope_blacklist`, `motor_drm`,
  `drm_targets`, `global_fields`, `process_overrides`, ออบเจกต์ `COPG-VD` (Build fields), รายการ
  `COPG-VD-Delete` และออบเจกต์ `COPG-VD-Settings` (`resetprop`, `autoupdate`, `spoof_version`)
  [ข้อมูลอ้างอิงการตั้งค่า](CONFIGURATION.md) อธิบายแต่ละรายการ
- `"spoof_version": "force"` จะถูกปฏิเสธเมื่อมันมาจากไฟล์บนดิสก์และถูกลดระดับเมื่ออ่าน ดังนั้นการกู้คืน
  สำรองข้อมูลเก่าจึงไม่สามารถเปิดใช้งานมันกลับมาอย่างเงียบ ๆ ได้ ให้ตั้งนโยบายเวอร์ชันผ่านการตั้งค่า ไม่ใช่
  ด้วยการเขียน `force` ด้วยมือ
- หลังจากแก้ไขไฟล์ ให้รัน **`analyze`** (ด้านล่าง): ไฟล์ที่พาร์สไม่ได้จะทำให้โมดูลสปูฟ **ไม่มีอะไรเลย** และมี
  เพียง logcat เท่านั้นที่บอก

การตั้งค่าที่เปลี่ยนแปลงจะไปถึงแอปเมื่อโปรเซสเริ่มทำงานครั้งถัดไป properties ที่ส่งผ่าน `resetprop`
สามารถนำไปใช้ใหม่ได้โดยไม่ต้องรีบูต (`service.sh --props-only`) แต่ฟิลด์ `android.os.Build.*` ถูกเขียน
โดยไลบรารี Zygisk เมื่อ zygote เริ่มทำงาน ดังนั้น **จำเป็นต้องรีบูต** เพื่อให้ฟิลด์เหล่านั้นไปถึงแอป

## สัญญาเชลล์

```
sh /data/adb/modules/COPG-VD/fingerprint-update.sh <verb> [arg]
```

สคริปต์พิมพ์บรรทัดที่มนุษย์อ่านได้, บรรทัดที่เครื่องอ่านได้จะขึ้นต้นด้วย `status:` รหัสออกของมันคือ `0`
เมื่อสำเร็จและไม่ใช่ศูนย์เมื่อล้มเหลว

| Verb | ทำอะไร | ผลลัพธ์ทั่วไป |
|---|---|---|
| `check` | เปรียบเทียบโปรไฟล์ที่ติดตั้งกับ upstream build ที่ใหม่ที่สุด ไม่เขียนอะไรเลย | `status: update-available` \| `status: up-to-date` \| `status: local-newer` \| `status: no-config` |
| `apply` | ดึงโปรไฟล์ที่ใหม่ที่สุดและผสานเข้ากับการตั้งค่า (เฉพาะ build fields, คีย์อื่นของคุณถูกรักษาไว้) | `status: applied` \| `status: up-to-date` \| `status: local-newer` \| `status: analyze-red` \| `status: skipped-custom-device` \| `status: failed` |
| `analyze` | ตรวจสอบการตั้งค่าตามที่เป็นอยู่ (การพาร์ส, เวอร์ชันเทียบกับ ROM, ความสอดคล้องของ fingerprint, คีย์ที่ไม่รู้จัก, วันที่, props) พิมพ์รายงาน, รหัสออกสะท้อนผลที่เป็น red/warn | รายงานแบบข้อความ |
| `fetch-index` | ดาวน์โหลดและตรวจสอบดัชนีอุปกรณ์ที่ลงนามแล้ว และพิมพ์มันออกมา (`index.json`) | JSON ของดัชนี \| `status: sig-failed` \| `status: download-failed` |
| `fetch <path>` | ดาวน์โหลด `build.prop` ของอุปกรณ์หนึ่ง (เส้นทางจากดัชนี เช่น `pixel-9a/latest.prop`) และเขียน build fields ของมันลงในการตั้งค่า | `status: fetched` \| `status: bad-path` \| `status: map-failed` \| `status: write-failed` |
| `sync-settings` | ย้ายสถานะ/การตั้งค่าจากโครงร่างแบบแบนเดิมไปยัง `/data/adb/COPG-VD/` | - |
| `migrate` | การย้ายการตั้งค่าแบบครั้งเดียวระหว่างเวอร์ชันของโมดูล | `status: migrated` \| `status: nothing-to-migrate` |
| `boot` | การอัปเดตอัตโนมัติหนึ่งครั้งต่อการบูต, มีไว้สำหรับ `service.sh` ไม่ใช่การใช้งานแบบโต้ตอบ | เขียน `update.status` |

การดาวน์โหลดทุกครั้งถูกตรวจสอบก่อนใช้งาน (ตัวดาวน์โหลดบนอุปกรณ์เพียงตัวเดียวคือ busybox `wget` ซึ่งไม่
สามารถตรวจสอบ TLS ได้) และตัวอัปเดตโปรไฟล์จะไม่ย้อนกลับ: upstream build ที่เก่ากว่าตัวที่ติดตั้งไว้จะถูก
ปฏิเสธ ดัชนีฟีดและ `.prop` ทุกไฟล์มีลายเซ็น ed25519 แบบแยกที่ถูกตรวจสอบก่อนที่จะอ่านเนื้อหา

## โฟลว์ของเอเจนต์ทั่วไป

- **รักษาโปรไฟล์ให้สดใหม่:** `check`; ถ้า `status: update-available` ให้ `apply`; จากนั้นรีบูตเพื่อให้
  `Build.*` ใหม่ไปถึงแอป
- **สลับไปยังโปรไฟล์ Pixel อื่น:** `fetch-index`, เลือกเส้นทางอุปกรณ์จากดัชนี, `fetch <path>`, รัน
  `analyze` เพื่อยืนยันว่าการตั้งค่าสอดคล้องกัน จากนั้นรีบูต
- **เปลี่ยนขอบเขตหรือเอนจิน:** แก้ไข `scope_mode` (หรือสวิตช์เอนจิน) ในไฟล์การตั้งค่า, รัน `analyze`,
  จากนั้น `service.sh --props-only` สำหรับการเปลี่ยนแปลงที่ส่งผ่าน property หรือรีบูตสำหรับ Build fields

## ราวกันตก

- การเปลี่ยนการตั้งค่าหรือการนำโปรไฟล์ไปใช้จะเปลี่ยนสิ่งที่แอปเป้าหมายทุกตัวเห็น, ยืนยันเจตนาก่อนเขียน
  เช่นเดียวกับที่ WebUI ทำ
- อย่าผ่อนปรนตัวป้องกันความสอดคล้องที่แท้จริง: SDK ถูกจำกัดไว้ที่ framework จริงภายใต้ทุกนโยบาย, ผู้ผลิต
  คงอยู่ในแนวเดียวกับส่วนที่เหลือของโปรไฟล์ และโปรไฟล์สำหรับอุปกรณ์อื่นจะถูกปฏิเสธ สิ่งเหล่านี้เป็นไปโดยเจตนา
  และต้องไม่ถูกข้าม
- การตั้งค่าคือพื้นผิวที่รองรับ อย่า scrape หรือทำให้ WebUI เองเป็นอัตโนมัติ
