# Архитектура

COPG-VD - это модуль Zygisk: небольшая нативная библиотека (`libspoof.so`), которую загрузчик Zygisk
внедряет в zygote, а оттуда - в процессы приложений. Всё, что она делает, - предоставляет
выбранную идентичность устройства процессам, которые вы нацеливаете. Приложения нет, и, помимо
опциональной загрузки профиля, сети нет.

## Жизненный цикл

1. **Старт zygote.** Когда zygote загружается, загрузчик вызывает `onLoad` модуля. Он
   читает `/data/adb/COPG-VD/COPG-VD.json` один раз: конфигурацию области действия и профиль.
2. **Fork приложения.** Для каждого приложения, которое zygote форкает, модуль решает в
   `preAppSpecialize`, попадает ли этот процесс в область действия:
   - **в основной области действия** (`playstore` / `global` / `whitelist` / `blacklist`), или
   - **в области действия DRM** (перечислен в `drm_targets`).
   Если ни то, ни другое, модуль **отсоединяется** от этого процесса (`dlclose`) и не оставляет
   в нём следа.
3. **Specialize.** Для процесса, который остаётся, движки применяются в `postAppSpecialize`,
   пока процесс всё ещё привилегирован.

Поскольку форки наследуют copy-on-write копию памяти zygote, каждое приложение стартует из конфигурации,
прочитанной при загрузке. Модуль перечитывает файл для каждого целевого процесса, только когда он действительно
изменился, так что только что запущенное или заново открытое приложение подхватывает отредактированный профиль - но само
решение об области действия принимается при старте zygote, поэтому **смена области действия, движков или
`drm_targets` требует перезагрузки**.

## Движки

Каждый независим и переключаем.

- **Поля Build (`motor_jni`).** Переписывает `android.os.Build.*` (и `Build.VERSION.*`)
  в целевом процессе через JNI, так что Java-код читает подменённые значения.
- **Хук свойств (`motor_prop_hook`).** Предоставляет подменённые системные свойства
  процессу через чистое (clean-room), для каждого процесса переотображение области свойств (`prop_virtualizer`).
  Это переотображение памяти, а не хук функции, поэтому нет следа захуканной функции.
- **resetprop (на уровне всего устройства).** Записывает системные свойства по группам - идентичность, версия,
  состояние загрузки, SELinux, adb/usb, анти-эмулятор, плюс проход очистки. Их запускают загрузочные
  скрипты. В режиме с областью действия группы идентичности и версии оставляются в стороне (Zygisk доставляет их
  для каждого процесса); группы boot, lock и SELinux остаются глобальными, чтобы устройство было согласованным.
- **DRM / Widevine (`motor_drm`).** Хукает методы `MediaDrm`, которые сообщают уровень безопасности
  Widevine (`getSecurityLevel`, `getPropertyString`), и возвращает настроенный
  уровень. Хуки проверяются на null, поэтому некорректный профиль деградирует плавно, а не
  обрушивает приложение. `drm_targets` позволяет этому движку работать по собственному списку приложений, отвязанному от
  основной области действия.

## Чтение конфигурации

Внедрённый процесс работает в SELinux-домене zygote, который по умолчанию не может достичь
`/data/adb`. Модуль поставляет собственный `sepolicy.rule`, чтобы это разрешить, и, в качестве запасного варианта,
может читать конфигурацию через свой открытый каталог модуля (`getModuleDir`), так что он продолжает
работать, даже если какая-то сборка Zygisk перестанет предоставлять этот путь. Файл парсится небольшим
встроенным JSON-парсером (`jsmn`); файл, который не парсится, означает, что модуль не подменяет ничего.

## Поддержание актуальности профиля

`fingerprint-update.sh` обновляет поля build из новейшего заводского образа Google,
из WebUI или один раз за загрузку. Он использует собственный встроенный загрузчик модуля (а не `curl`/`wget`
из `PATH`), проверяет каждое значение перед использованием, никогда не откатывается назад и отклоняет
профиль, который подменяет другое устройство. `android.os.Build` записывается при старте zygote, поэтому
новые значения доходят до приложений при следующей перезагрузке. Смотрите [USER-GUIDE.md](USER-GUIDE.md) для пользовательской
стороны и [CONFIGURATION.md](CONFIGURATION.md) для полей.

## Почему версия Android не подменяется по умолчанию

Повышение `SDK_INT` / `ANDROID_VERSION` выше того, чем фреймворк ROM является на самом деле, заставляет приложения
вызывать API, которых не существует, что обрушивает приложения Google и перезагружает телефон в
softloop. Поэтому группа версии по умолчанию выключена и защищена за
`spoof_version`. Модуль читает настоящую версию из `/system/build.prop`, никогда из
`getprop`, потому что `getprop` - это именно то, что он фальсифицирует. Смотрите ловушку в
[USER-GUIDE.md](USER-GUIDE.md#the-android-version-trap).
